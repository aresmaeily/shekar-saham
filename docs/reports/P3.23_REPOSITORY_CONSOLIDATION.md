# P3.23 — Repository Consolidation, Iran Market Focus & Final Product Architecture

تاریخ اجرا: 2026-08-07

## Scope

این فاز برای تثبیت Repository و آماده‌سازی مسیر Production اجرا شد. هیچ Feature، Engine، Dashboard یا بازار جدیدی اضافه نشد.

## Research Snapshot

Repository واقعی از GitHub `https://github.com/aresmaeily/shekar-saham` اسکن شد.

### ساختار واقعی

- Backend: `backend/app` با FastAPI
- API: `backend/app/api/{routes,auth,excellent,chart,forex}.py`
- Engines: `backend/app/engines`
- Data: `backend/app/data`
- Services: `backend/app/services`
- Frontend فعلی: `frontend` با HTML/CSS/JS ماژولار و `lightweight-charts`
- Desktop اصلی: `electron` برای Windows
- Android scaffold: `android-app`
- CI: `.github/workflows/ci.yml`
- `frontend-next`: در Repository وجود ندارد.

### وضعیت محصول

اولویت واقعی محصول در Repository فعلی باید این باشد:

1. بورس ایران و تابلوخوانی
2. AI/Explainability موجود
3. Windows Desktop با Electron
4. حفظ اسکلت Global Markets بدون توسعه جدید

- Backtest و Risk: `/api/backtest/run`, `/api/backtest/history`, `/api/risk/*`

## Architecture Decisions

1. `frontend` فعلی Frontend عملیاتی محصول باقی می‌ماند.
2. `frontend-next` چون در Repository وجود ندارد، اقدامی برای Archive/Delete انجام نشد.
3. Electron/Windows مسیر اصلی Desktop باقی می‌ماند.
4. Android scaffold حفظ شد و توسعه‌ای روی آن انجام نشد.
5. Global Markets فقط به صورت اسکلت موجود حفظ شد؛ توسعه جدید انجام نشد.
6. تمرکز معماری روی بورس ایران، موتورهای تابلوخوانی، فیلتر، نقشه بازار، بک‌تست و AI موجود حفظ شد.

## Changes Done

- حذف پوشه ریشه‌ای `tests/` چون نسخه‌ای کاملاً تکراری از بخشی از `backend/tests/` بود و اجرای `pytest backend/tests tests` را با خطای import mismatch خراب می‌کرد.
- اصلاح `Dockerfile` برای حذف وابستگی Build به وجود پوشه local `data/` در Git؛ اکنون Docker image خودش `/app/data` را می‌سازد.
- افزودن این گزارش به `docs/reports/P3.23_REPOSITORY_CONSOLIDATION.md`.

## Fixed Issues

- رفع خطای Collection هنگام اجرای همه تست‌ها به‌علت تست‌های تکراری هم‌نام در `tests/` و `backend/tests/`.
- رفع ریسک شکست Docker build در Clone تمیز، چون پوشه `data/` توسط `.gitignore` حذف/نادیده گرفته می‌شود ولی Dockerfile قبلاً آن را Copy می‌کرد.

## Remaining Issues / Risks

- مستندات قدیمی متعدد در `docs/` وجود دارند و نیاز به آرشیو کنترل‌شده دارند، اما برای جلوگیری از حذف اشتباه در این فاز دست‌نخورده باقی ماندند.
- چند تست import بلااستفاده دارند؛ CI فعلی فقط `backend/app` را با pyflakes بررسی می‌کند، بنابراین Regression عملی ایجاد نمی‌کند.
- نسخه Electron هنوز Server محلی `http://127.0.0.1:8000` را فرض می‌کند و برای بسته Production کامل نیازمند فرآیند نصب/اجرای Backend است.
- داده واقعی TSETMC/BRSAPI وابسته به دسترسی شبکه و تنظیمات محیطی است؛ حالت Mock fallback موجود است.
