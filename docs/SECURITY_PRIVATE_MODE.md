# 🔐 حالت خصوصی و امنیت — فقط مالک (v1.5)

## فعال‌سازی حالت خصوصی (خروجی منوها فقط برای شما)

در فایل `.env` (یا متغیر محیطی) کنار سرور:

```bash
# حالت خصوصی — همه خروجی‌ها قفل می‌شوند
PRIVATE_MODE=1

# رمز ورود شما (در UI با این رمز وارد می‌شوید)
PRIVATE_PASSWORD=یک-رمز-خیلی-قوی-تصادفی

# کلید API برای اسکریپت/اتوماسیون (اختیاری اما توصیه‌شده)
API_KEY=یک-کلید-تصادفی-طولانی
```

بعد از این، هر بازدیدکننده‌ای (از جمله خودتان) اول **صفحه قفل** می‌بیند:
- بدون رمز → هیچ API و خروجی منویی در دسترس نیست (سرور 401 می‌دهد)
- با رمز درست → توکن ۲۴ساعته امضاشده صادر می‌شود و همه خروجی‌ها فعال می‌شوند
- توکن در localStorage مرورگر شما ذخیره می‌شود → تا ۲۴ ساعت بدون ورود مجدد
- دکمه «🚪 خروج» در بالای صفحه برای پایان جلسه

## لایه‌های امنیتی موجود (از قبل + جدید)

| لایه | توضیح |
|------|-------|
| **توکن جلسه HMAC-SHA256** | امضاشده با رمز شما + انقضا ۲۴ساعت — قابل جعل نیست |
| **ورود زمان‌ثابت (timing-safe)** | مقایسه رمز با `hmac.compare_digest` — بدون نشت زمانی |
| **قفل همه /api** | در PRIVATE_MODE همه اندپوینت‌ها (به‌جز health/login) نیاز به توکن دارند |
| **هدرهای OWASP** | X-Frame-Options, X-Content-Type-Options, CSP, HSTS, Referrer-Policy |
| **Rate Limit** | ۱۲۰req/min عمومی · ۲۰/min مسیرهای سنگین · ۱۵/min مسیرهای حساس |
| **WebSocket محافظت‌شده** | WS هم در حالت خصوصی نیاز به توکن دارد (کد 4401 اگر نادرست باشد) |
| **Audit لاگ** | تلاش‌های ناموفق ورود و مسیرهای حساس لاگ می‌شوند |
| **بدون کلید پیش‌فرض** | اگر API_KEY ست نشود، هیچ کلیدی وجود ندارد |
| **CORS سخت‌گیرانه** | فقط localhost به‌طور پیش‌فرض — در prod از env تنظیم کنید |

## توصیه‌های تکمیلی برای استقرار واقعی

1. **HTTPS** — پشت Nginx/Caddy با TLS اجرا کنید؛ HSTS خودکار فعال می‌شود.
2. **رمز قوی** — حداقل ۲۰ کاراکتر تصادفی؛ `openssl rand -hex 24` برای API_KEY.
3. **نسخه‌برداری** — `data/shekar.db` را بکاپ بگیرید.
4. **محدود کردن دسترسی شبکه** — با فایروال، پورت سرور را فقط به IP خودتان/شبکه خصوصی باز کنید.
5. **عدم اشتراک توکن** — توکن فقط در مرورگر شماست؛ اگر لو رفت، رمز را عوض کنید (توکن‌ها با رمز امضا می‌شوند و باطل می‌شوند).
