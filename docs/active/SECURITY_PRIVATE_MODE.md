## فعال‌سازی حالت خصوصی (خروجی منوها فقط برای شما)

در فایل `.env` (یا متغیر محیطی) کنار سرور:

```bash
# حالت خصوصی — همه خروجی‌ها قفل می‌شوند
PRIVATE_MODE=1

# رمز ورود شما (در UI با این رمز وارد می‌شوید)
PRIVATE_PASSWORD=یک-رمز-خیلی-قوی-تصادفی

# کلید API برای اسکریپت/اتوماسیون (اختیاری اما توصیه‌شده)
API_KEY=یک-کلید-تصادفی-طولانی
```

- رمز ورود می‌تواند `PRIVATE_PASSWORD` باشد؛ اگر خالی باشد `API_KEY` نقش رمز را دارد (`backend/app/api/auth.py:36`).
- `PRIVATE_MODE` بدون هیچ رمزی اجازه استارت ندارد — سرور fail-closed با خطا متوقف می‌شود (`backend/app/core/security.py:231-233`).

بعد از این، هر بازدیدکننده‌ای (از جمله خودتان) اول **صفحه قفل** می‌بیند:
- بدون رمز → هیچ API و خروجی منویی در دسترس نیست (سرور 401 می‌دهد)
- با رمز درست → توکن ۲۴ساعته امضاشده صادر می‌شود و همه خروجی‌ها فعال می‌شوند
- توکن نشست در **کوکی HttpOnly** به نام `shekar_session` ذخیره می‌شود (`SameSite=Strict`؛ با `COOKIE_SECURE=1` فقط روی HTTPS) → جاوااسکریپت به توکن دسترسی ندارد و تا ۲۴ ساعت بدون ورود مجدد می‌مانید (`backend/app/api/auth.py:47-57`، `backend/app/core/security.py:121-137`)
- برای اسکریپت/اتوماسیون به‌جای توکن از هدر `X-API-Key` استفاده کنید (هیچ توکنی از API خوانده نمی‌شود)
- دکمه «🚪 خروج» در بالای صفحه برای پایان جلسه (`POST /api/auth/logout` کوکی را پاک می‌کند)

## لایه‌های امنیتی موجود (از قبل + جدید)

| لایه | توضیح |
|------|-------|
| **نشست کوکی HttpOnly** | توکن جلسه HMAC-SHA256 امضاشده با رمز شما + انقضا ۲۴ساعت — قابل جعل نیست؛ در کوکی `shekar_session` با `httponly` و `samesite=strict` نگهداری می‌شود و JS به آن دسترسی ندارد |
| **ورود زمان‌ثابت (timing-safe)** | مقایسه رمز با `hmac.compare_digest` — بدون نشت زمانی |
| **قفل همه /api** | در PRIVATE_MODE همه اندپوینت‌ها نیاز به احراز دارند؛ فقط `/api/auth/*` و `/api/health` همیشه بازند و اندپوینت‌های probe عمومی (`/api/status`، `/api/live/status`) بدون احراز فقط پاسخ **redact‌شده** می‌دهند (بدون داده بازار) |
| **هدرهای OWASP** | X-Frame-Options: DENY، X-Content-Type-Options، CSP سخت‌گیرانه (اسکریپت فقط self)، HSTS روی HTTPS، Referrer-Policy + X-XSS-Protection و Permissions-Policy |
| **Rate Limit** | ۱۵۰req/min عمومی · ۲۵/min مسیرهای سنگین · ۱۵/min مسیرهای حساس · **ورود: ۵/min و ۲۰/ساعت** (ضد brute-force) |
| **بررسی Origin (CSRF)** | درخواست‌های POST/PUT/PATCH/DELETE با Origin خارج از هاست → 403 |
| **WebSocket محافظت‌شده** | WS هم در حالت خصوصی نیاز به احراز دارد (کوکی نشست یا `X-API-Key` یا Bearer؛ برای سازگاری کلاینت‌های WS پارامترهای `api_key`/`token` در query هم پذیرفته می‌شود و لاگ می‌شود) — کد 4401 اگر احراز نشود |
| **Audit لاگ** | مسیرهای حساس (notify/config/portfolio/confluence/notify-now) audit می‌شوند؛ هر 401 روی مسیرهای محافظت‌شده در متریک `shekar_auth_failures_total` شمرده می‌شود؛ فشار ورود (429) با warning لاگ می‌شود |
| **اعتبارسنجی امنیتی استارت** | هنگام بالا آمدن سرور: PRIVATE_MODE بدون رمز = خطا؛ در production نبودِ احراز، `FERNET_KEY`/`API_KEY` یا `COOKIE_SECURE=1` = خطا (fail-closed) |
| **Redaction مسیرهای عمومی** | پاسخ probeهای بدون احراز، بدون داده بازار و با `"redacted": true` برگردانده می‌شود |
| **بدون کلید پیش‌فرض** | اگر API_KEY ست نشود، هیچ کلیدی وجود ندارد |
| **CORS سخت‌گیرانه** | فقط localhost به‌طور پیش‌فرض — در prod از `CORS_ORIGINS` تنظیم کنید؛ `*` در حالت prod به localhost برمی‌گردد |
| **حالت `?legacy` (عیب‌یابی)** | با پارامتر `?legacy` فقط فرانت‌اند قدیمی برای دیباگ بارگذاری می‌شود؛ احراز سمت سرور روی همه APIها بدون تغییر است — این حالت هیچ دورزدن احراز ایجاد نمی‌کند |

## توصیه‌های تکمیلی برای استقرار واقعی

1. **HTTPS** — پشت Nginx/Caddy با TLS اجرا کنید؛ HSTS خودکار فعال می‌شود و `COOKIE_SECURE=1` را در `.env` بگذارید.
2. **پروکسی معکوس** — فقط اگر X-Forwarded-For قابل اعتماد است `TRUST_PROXY=1`؛ در غیر این صورت rate limit با جعل هدر دور زده می‌شود.
3. **رمز قوی** — حداقل ۲۰ کاراکتر تصادفی؛ `openssl rand -hex 24` برای API_KEY.
4. **نسخه‌برداری** — `data/shekar.db` را بکاپ بگیرید.
5. **محدود کردن دسترسی شبکه** — با فایروال، پورت سرور را فقط به IP خودتان/شبکه خصوصی باز کنید.
6. **عدم اشتراک توکن** — توکن فقط در کوکی مرورگر شماست؛ اگر لو رفت، رمز را عوض کنید (توکن‌ها با رمز امضا می‌شوند و باطل می‌شوند).
