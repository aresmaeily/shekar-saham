## G — Filter DSL Design

The DSL remains simple, declarative and UI-independent.

Supported:

- Boolean expressions: `and`, `or`, `not`, plus normalized `AND`, `OR`, `NOT`, `&&`, `||`.
- Comparisons: `==`, `!=`, `<`, `<=`, `>`, `>=`, `in`, `not in`.
- Arithmetic: `+`, `-`, `*`, `/`.
- String containment: `contains(industry, 'فلز')` and `industry contains فلز`.
- Field aliases: `close`, `price`, `volume`, `avg_volume`.
- Indicator references: `sma(period)`, `avg_volume(period)`, `rsi(period)`, `high(period)`, `low(period)`.
- Persian/Arabic digit normalization.

Backward compatibility:

- Existing old expressions remain valid.
- Saved filters remain strings.
- `compile_filter()` still returns a validated AST expression.

## I — Security Model

The DSL rejects arbitrary code execution surfaces:

- no `eval`
- no `exec`
- no arbitrary function calls
- no arbitrary imports
- no attributes like `symbol.__class__`
- no subscripts like `tags[0]`
- no keywords in function calls
- no network/filesystem/shell access
- expression length limit
- AST node-count limit
- AST depth limit

Security tests cover import injection, attribute access, subscript access and invalid functions.

## J — Strategy Framework

New file:

```text
backend/app/domain/strategy.py
```

Contracts:

- `StrategyMetadata`
- `StrategySignal`
- `StrategyContext`
- `Strategy` protocol
- `FilterStrategy`
- `StrategyRegistry`

`FilterStrategy` adapts a safe Filter DSL expression into strategy signals. It does not backtest or forward-test.

Future chain prepared:

```text
Strategy → Filter / Indicators → Signal → Backtest → Walk-Forward → Forward Test → Paper Trading
```

Only the contract and filter-to-signal boundary are implemented in P3.26.
