# P3.25 Final Report — Iran Market Data & Domain Stabilization

Last updated: 2026-08-07

## A — Executive Summary

P3.25 focused on stabilizing the data/domain foundation for the Iran stock market core. The phase did not add a new market, dashboard, AI product, strategy builder, forward test, UI redesign, or mobile/global expansion.

Main outcomes:

- Added canonical data-trust classification: `live`, `mixed`, `mock`, `synthetic`.
- Preserved backward-compatible `trust_level` (`live`, `mixed`, `synthetic`).
- Added explicit domain contracts for provenance, Iran instruments, market sessions, and OHLCV bars.
- Updated data-quality scoring so mock/synthetic snapshots cannot be reported as live trust.
- Added `data_trust` metadata to key market-intelligence service/API outputs.
- Added tests covering data trust, Persian instrument encoding, and OHLCV contracts.
- Added architecture documentation for Iran Market Data & Domain boundaries.

## D — Research Findings

Reviewed minimum required paths and related consumers:

- `backend/app/core/config.py`
- `backend/app/models/schemas.py`
- `backend/app/data/providers.py`
- `backend/app/data/mock_market.py`
- `backend/app/data/store.py`
- `backend/app/engines/data_quality.py`
- `backend/app/services/market_service.py`
- `backend/app/api/routes.py`
- relevant frontend consumers through existing API smoke/static validation

Findings:

1. Provider selection and fallback are centralized in `MarketDataProvider`.
2. TSETMC/BRSAPI snapshots and mock data all normalize into `SymbolSnapshot`.
3. Existing `trust_level` is backward-compatible but too coarse to distinguish mock from synthetic.
4. Data-quality scoring previously started from `trust='live'` and did not consider `snapshot.source`, allowing fresh mock snapshots to appear live in quality distribution.
5. API responses already exposed `trust_level` in many places but lacked a richer canonical `data_trust` object.
6. Historical data is currently SQLite/tick based and partial; no new data lake was introduced.
7. Market session metadata was not explicit; P3.25 adds a contract boundary but does not infer live session state.

## H — Provider / Adapter Changes

No provider fetch logic was rewritten.

Added in `backend/app/core/config.py`:

- `classify_data_trust_state(source)`
- `build_data_trust_context(source, ...)`

Current mapping:

| Source | `data_trust.state` | legacy `trust_level` |
|---|---|---|
| `tsetmc`, `brsapi`, `tsetmc_legacy` | `live` | `live` |
| `mock`, `mock_fallback` | `mock` | `synthetic` |
| `synthetic`, `bootstrap`, `demo` | `synthetic` | `synthetic` |
| `cache`, `auto`, `unknown`, `none`, empty | `mixed` | `mixed` |

This preserves old safeguards while giving the product a clearer domain contract.
