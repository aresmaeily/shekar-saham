## Part 1 — Indicator catalog & installation architecture (directive §B4; M5)

**Catalog (`indicator_catalog.py`, `IC-1.0.0`):** 14 built-in entries spanning all six required categories — TREND{sma, ema, adx}, MOMENTUM{rsi, macd, stochastic, williams, cci}, VOLATILITY{atr, bollinger}, VOLUME{obv, vwap}, BREADTH{advance_decline_line}, MARKET_STRUCTURE{new_high_rate}. Every entry declares: precise `math_definition` (formula + warm-up), typed parameter ranges (min < default < max, validator-enforced), `warmup_bars`, `missing_data` behavior (`ZERO_BEFORE_WARMUP`/`PARTIAL_WINDOW`/`SKIP`/`FAIL_CLOSED`), `repaint` declaration (`NON_REPAINTING`/`REPAINTS_LAST_BAR`/`SESSION_DEPENDENT` — VWAP honestly SESSION_DEPENDENT), `lookahead_declared=False` (validator-enforced for ALL), `series_inputs`, `requires_volume`, `permissions` from a fixed whitelist, `engine_ref` (existing audited engine) + `reference_ref` (independent implementation) with a `dual_implementation` honesty flag where engine==reference (sma/ema/rsi). `validate_catalog()` resolves every dotted ref to a callable and returns [] healthy.

**Independent references (`indicator_reference.py`):** textbook implementations written from scratch (deliberately not calling `app.engines.indicators`), the basis of cross-validation: engine vs reference agree to engine rounding precision on deterministic 80-bar fixtures (audit-verified: macd ≤4.9e-9 at d=8, bollinger ≤5e-7 at d=6, stochastic/obv ≤5e-5 at d=4, all bit-identical pre-rounding). adx/cci/williams are engine-only today with `reference_ref=None` recorded honestly.

**Installation architecture (`indicator_manager.py`):** metadata-only lifecycle — NO downloaded or user code is ever executed (recursive forbidden-key scanner rejects `code/script/exec/eval/lambda/__*` at any depth; permission whitelist `{series:read, chart:overlay, chart:pane}`; reserved `builtin.*` namespace; checksum verification over the canonical definition; size ≤256 KiB / ≤64 entries; JSON-only packages). State machine: install (enabled=False by default) → enable (fail-closed on missing series inputs) / disable / remove (builtin removal FORBIDDEN) / version check (major-equal + minor≥) / template compose (dependency + warm-up composition) / export-import manifest with `manifest_digest()` determinism. Persistence is a caller concern (documented) — no silent disk writes.

**Runtime surface:** `/api/v10/indicators` (catalog), `/{id}` (full spec + math definition), `/{id}/compute` (typed param validation incl. range/type rejection, audited-implementation resolution, declarations echoed, `data_class: SYNTHETIC_SEEDED` + Persian note; breadth ADL honestly refuses OHLCV computation). Frontend Indicator Manager view consumes the catalog with Persian labels.

## Part 2 — AI market analyst: provenance & evaluation report (directive §F; M11)

`backend/app/engines/symbol_analyst.py` (`ANALYST-1.0.0`), 65 tests — deterministic rules engine, **no LLM call** (`generated_by: "deterministic-rules-v1 (no LLM call; provider path is owner-gated and disconnected)"`).

**Claim taxonomy & provenance:** five kinds — `OBSERVED_FACT`, `CALCULATED_METRIC` (both deterministic: confidence=None), `MODEL_INTERPRETATION`, `SCENARIO`, `RECOMMENDATION` (rule-based: confidence bounded 0.35–0.65). Every claim carries: source class, as-of ts, freshness bars, timeframe, evidence ref, trust class (canonical 7-value taxonomy), calculation ref (formula id) where applicable, and `conflict_with` links. Audit D independently verified: 20 claims in the reference run — 6 OBSERVED_FACT + 8 CALCULATED_METRIC with zero confidence values; 3 MODEL_INTERPRETATION + 3 SCENARIO within the bounded band; 100% provenanced; Persian text present on every claim.

**Synthesis rules (all documented with rule ids):** per-timeframe EMA20/50 arrangement + slope, ±3-window swing structure, ATR(14) percentile (elevated ≥0.7 / compressed ≤0.3), volume-vs-SMA20 ratio, Wilder RSI(14), MACD sign, Bollinger position; MTF agreement matrix with daily-priority disagreement rule (MTF-1); scenarios keyed ONLY to computed swing levels with explicit invalidation conditions (e.g., "close below swing low for 2 consecutive daily bars") — no invented numbers, base scenario carries no key level by design; fundamentals/sector/strategy-signal contexts enter as explicit `available:false` sections until their sources are admitted.

**Content bans (fail-closed):** `forbidden_terms_scan` covers EN+FA banned terms (target price, guarantee, تضمین, قطعی, …) across ALL text fields; `analyze_symbol` REFUSES to return if its own scan finds anything; tests include a positive control (planted violating claims ARE caught). No guaranteed forecasts, fabricated citations, invented fundamentals, or unsupported target prices can be emitted by construction + scan.

**Evaluation summary (honest):** the analyst is evaluated for determinism (same input → same digest), provenance completeness, unavailability honesty (missing inputs become claims; MTF agreement INSUFFICIENT_DATA when weekly absent), conflict surfacing (daily-vs-weekly fixtures → DISAGREE with conflict links), and ban enforcement. It is NOT evaluated as a predictive system — it makes no forecasts by design; accuracy-style metrics are NOT-APPLICABLE.

**Runtime surface:** `/api/v10/analyst/{symbol}` — daily seeded SYNTHETIC + weekly honestly `RESAMPLED_FROM_1D_SYNTHETIC`; hourly/fundamentals/sector/signals explicit MISSING with reasons; trust envelope from `market_service`; deterministic digest verified over the API.
