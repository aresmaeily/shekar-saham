# P3.31 Live Data & Data Trust Hardening Report

Date: 2026-08-09

## 1. Research Findings

Baseline at phase start:

```text
Local HEAD: c5181ad1ecc14a2c1c8a292029adfe3827fa9e26
Branch: main
Remote GitHub HEAD: 26a2d120b596aa298a40b2ebc6952310658f45b5
```

Existing implementation already had `live`, `mixed`, `mock`, `synthetic` trust states in `backend/app/core/config.py` and `backend/app/models/schemas.py`.

Gaps found:

- No canonical `stale` or `unavailable` state.
- `build_data_trust_context()` did not include `checked_at`, `age_sec`, `stale_after_sec`, or `stale` metadata.
- Provider failure/fallback metadata existed as `MarketDataProvider.last_error` and `last_source` but was not included in the trust context.
- Fundamental outputs were based on synthetic statements but did not carry explicit `fundamental_source` and `is_synthetic` labels.
- AI/backtest warnings did not explicitly cover `stale` and `unavailable` states.
- Frontend trust renderer did not fully represent all data trust states.

## 2. Architecture Decisions

P3.31 uses a minimal backward-compatible extension:

```text
legacy trust_level = live | mixed | synthetic
new data_trust.state = live | mixed | mock | synthetic | stale | unavailable
```

No provider rewrite, no engine rewrite, no trading math changes, no UI redesign, and no new market or LLM integration were introduced.

## 3. Changes Implemented

- Extended canonical trust states in config and schema.
- Added freshness metadata to `data_trust`.
- Added provider failure/fallback metadata to `data_trust`.
- Added explicit synthetic fundamental metadata.
- Extended AI trust warnings/confidence behavior for stale/unavailable.
- Extended backtest warnings for stale/unavailable.
- Extended frontend trust renderer to display live/mixed/mock/synthetic/stale/unavailable.
- Added focused regression tests for trust states, freshness, propagation, AI, backtest, and fundamental labels.

## 4. Bugs Found

| Severity | Issue |
|---|---|
| P1 | Stale live data could not be represented as a canonical state. |
| P1 | Missing provider data could not be represented as unavailable. |
| P1 | Provider failure reason was not propagated in data trust context. |

## 5. Bugs Fixed

- Added `stale` and `unavailable` states.
- Added freshness fields: `checked_at`, `age_sec`, `stale_after_sec`, `stale`.
- Added safe provider status fields: `fallback_source`, `error_code`.
- Added `fundamental_source=synthetic` and `is_synthetic=true` to deep/symbol fundamental output.
- Added stale/unavailable warnings and lower confidence handling in AI fallback outputs.
- Added stale/unavailable warnings in backtest reports.
- Added frontend labels for all trust states.

## 6. Data Trust State Model

| data_trust.state | legacy trust_level | Meaning |
|---|---|---|
| live | live | Provider data is live and within freshness threshold. |
| mixed | mixed | Partial/cached/unknown trust or live source without timestamp proof. |
| mock | synthetic | Demo/mock fallback data. |
| synthetic | synthetic | Generated/simulated data. |
| stale | mixed | Previously live/mixed data is older than freshness threshold. |
| unavailable | mixed | No usable provider data is available. |

## 7. Provider/Fallback Behavior

Provider code was not rewritten. Existing `last_source` and `last_error` are consumed by `MarketService.data_trust_context()`.

Example semantics:

```text
source=mock_fallback
state=mock
trust_level=synthetic
is_live=false
is_generated=true
fallback_source=mock
```

BRSAPI missing key is represented as safe metadata and never exposes a credential value.

## 8. Fundamental Trust Status

Current fundamental engine remains synthetic/demo. Calculations were not changed.

Service outputs now include:

## 9. AI Trust Validation

AI service still uses the existing fallback/rule-based provider. No LLM was added.

AI now warns for:

- mock
- synthetic
- stale
- unavailable
- mixed

Confidence is reduced for non-live states.

## 10. Backtest Trust Validation
