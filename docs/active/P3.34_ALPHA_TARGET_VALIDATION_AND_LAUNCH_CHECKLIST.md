# P3.34 — Alpha Target Validation and Launch Checklist

Date: 2026-08-09

Status terminology:

- `PASS`: executed successfully in the current environment.
- `READY`: artifact/checklist/script is ready for target execution.
- `PARTIAL`: partly prepared or partly validated.
- `NOT EXECUTED`: not executed in the current environment.
- `DEFERRED — TARGET SYSTEM REQUIRED`: requires the main Windows/target system.
- `BLOCKED`: cannot proceed without missing tool/credential/environment.
- `FAIL`: executed and failed.

## Browser E2E Checklist

Run on target system after backend starts:

1. Open `/`.
2. Confirm main dashboard loads.
3. Confirm trust banner/pill is visible and does not show LIVE for mock/synthetic/stale/unavailable.
4. Open `/symbol/فملی`.
5. Run or open Filter tab and verify API response.
6. Run Backtest tab and verify warning/trust status.
7. Call AI Assistant / Analyst / Optimizer through available UI/API workflow.
8. Check browser console for fatal JS errors.
9. Check network tab for failed API calls.
10. Verify RTL/Persian rendering.

## Target-System Runbook

### 1. Restore Full Project

Extract the latest full project ZIP.

```bash
cd shekar-saham
```

Expected:

```text
README.md, backend/, frontend/, electron/, docs/, scripts/ exist.
```

Failure:

```text
Missing required paths.
```

Recovery:

```text
Verify ZIP SHA-256 and re-extract.
```

### 2. Verify Git HEAD

```bash
git status
git log --oneline --decorate -10
git rev-parse HEAD
```

Expected:

```text
Working tree clean and HEAD equals the delivered commit.
```

### 3. Verify / Restore Origin

```bash
git remote -v
```

If missing and safe:

```bash
git remote add origin https://github.com/aresmaeily/shekar-saham.git
```

### 4. Configure `.env`

```bash
cp .env.example .env
```

Set secrets only on target system. Do not commit `.env`.

Required alpha values:

```text
PRIVATE_MODE=1
PRIVATE_PASSWORD=<target secret>
API_KEY=<target secret>
FERNET_KEY=<target secret>
DATA_SOURCE=auto|tsetmc|brsapi|mock
DATA_STALE_AFTER_SEC=300
```

### 5. Validate Environment

```bash
python scripts/validate_alpha_environment.py
```

Expected:

```text
Required files OK; secret values not printed.
```

### 6. Install Python Dependencies

```bash
cd backend
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
cd ..
```

### 7. Install Node Dependencies

Only if Electron validation is needed:

```bash
cd electron
npm install
cd ..
```

### 8. Start Backend

```bash
cd backend
PYTHONPATH=. python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --no-proxy-headers
```

### 9. Health Check

```bash
curl http://127.0.0.1:8000/api/health
```

Expected: HTTP 200 JSON.

### 10. API Smoke

```bash
python scripts/validate_alpha_runtime.py
```

Expected: `ok=true`.

### 11. Start/Verify Frontend

Open:

```text
http://127.0.0.1:8000
http://127.0.0.1:8000/symbol/فملی
```

### 12. Browser E2E

Use checklist above.

### 13. Verify Data Provider

```bash
python scripts/validate_providers.py --source tsetmc
```

If BRSAPI key is securely configured:

```bash
python scripts/validate_providers.py --source brsapi
```

### 14. Verify Data Trust

Expected for live only if actually live:

```text
data_trust.state=live
is_live=true
```

If mock/synthetic/stale/unavailable appears, do not call it live.

### 15. Verify Fundamental Safety

```bash
curl http://127.0.0.1:8000/api/fundamental/فملی/deep
```

Expected in current alpha unless real fundamental provider is added:

```text
fundamental_source=synthetic
is_synthetic=true
```

### 16. Verify AI

Use API or UI:

```bash
curl -X POST http://127.0.0.1:8000/api/ai/assistant -H "Content-Type: application/json" -d '{"question":"وضعیت بازار؟"}'
```

Expected:

```text
provider=fallback unless live AI is separately configured.
data_trust present.
```

### 17. Verify Backtest

```bash
curl -X POST http://127.0.0.1:8000/api/backtest/run -H "Content-Type: application/json" -d '{"strategy_filter":"entry_score >= 60","bars":80}'
```

Expected:

```text
HTTP 200, data_trust present, warnings present for non-live data.
```

### 18. Verify Electron

Start backend first.

```bash
cd electron
npm start
```

Expected: window loads backend UI.

### 19. GitHub Sync

Only with secure credentials:

```bash
git push origin main
git ls-remote origin refs/heads/main
```

Expected: remote HEAD equals local HEAD.

### 20. Remote HEAD Verification

Do not claim GitHub sync until `git ls-remote` matches the local commit.

### 21. Alpha Gate

Alpha can be called ready only if required target-system checks pass or are explicitly accepted as deferred.

### 22. Backup

Create a post-validation backup and record SHA-256.

### 23. Final Launch Decision

Use:

```text
ALPHA READY
ALPHA READY WITH CONDITIONS
ALPHA BLOCKED
```

based only on evidence.
