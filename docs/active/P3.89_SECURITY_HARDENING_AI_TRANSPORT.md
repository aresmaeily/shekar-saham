# P3.89 — Security hardening of AI transport residuals

Date: 2026-08-15
Started from verified P3.88 HEAD `a13b778926389235610a774be2b4369559c5416f`

## Decision: OPTION A

Residual C is a real transport security defect. Official Gemini REST auth is
the `x-goog-api-key` header. Query-string `?key=` puts the server-side
credential in the URL, so it can leave process memory via proxies, URL scans,
and httpx exception causes the first time Gemini is enabled.

Google Cloud: avoid query-parameter API keys; use `x-goog-api-key`.
Gemini API reference uses the same header.

## What changed

`_build_provider_http("gemini")` now sends `x-goog-api-key` and does not
append the key to the URL. OpenAI/Anthropic/Groq/Azure header auth is
unchanged.

## What was not a defect

- A/B: `external_runtime` / provider mode remain resolver/config labels.
  Frontend/Electron do not read them.
- D: empty-prompt `"ping"` is not reachable from production capability paths.
- No committed real AI secret was found.
