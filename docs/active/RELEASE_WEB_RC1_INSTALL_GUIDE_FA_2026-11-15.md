## ۲. نصب گام‌به‌گام

```bash
# 1) دریافت کد در SHA دقیق
git clone https://github.com/aresmaeily/shekar-saham.git
cd shekar-saham
git checkout release/web-rc1
git rev-parse HEAD   # این SHA را با اثبات انتشار RC1 مقایسه کنید

# 2) ساخت فایل تنظیمات از قالب production (فقط placeholder؛ بدون هیچ محرمانهٔ واقعی)
cp .env.production.example .env
nano .env    # همهٔ مقادیر change-me را با مقادیر قوی عوض کنید
chmod 600 .env
# اگر همین قالب را بدون تغییر رها کنید، اپ در راه‌اندازی رد می‌شود (fail-closed)

# 3) ساخت و اجرا
docker compose up -d --build

# 4) سلامت
curl http://127.0.0.1:8000/api/health
# پاسخ موردانتظار: {"ok":true, ... , "data_trust":{"state":"mock", ...}}
```

وب‌اپلیکیشن روی `http://127.0.0.1:8000` در دسترس است (پورت/میزبان از `HOST`/`PORT` در entrypoint قابل تغییر است؛ در production پشت Nginx/Caddy با HTTPS قرار دهید).

## ۳. تنظیمات الزامی production (ناموفق-اگر-نامطمئن)

- `PRIVATE_MODE=1` + `PRIVATE_PASSWORD` قوی (یا `API_KEY`): بدون آن خروجی‌ها باز است.
- `COOKIE_SECURE=1`: کوکی نشست فقط روی HTTPS.
- `TRUST_PROXY=1` **فقط** پشت پروکسی معکوس معتبر؛ در غیر این صورت X-Forwarded-For قابل جعل است و rate-limit دور زده می‌شود.
- `FERNET_KEY`: کلید Fernet پایدار برای رمزنگاری توکن‌های اعلان؛ بدون آن کلید موقت (ephemeral) است و پس از ری‌استارت توکن‌های ذخیره‌شده قابل رمزگشایی نیستند (هشدار صریح در لاگ راه‌اندازی).
- `CORS_ORIGINS`: فقط مبدأ واقعی خودتان؛ ستاره ممنوع.
- اپ با مقادیر placeholder بالا **نمی‌آید**: `validate_security_configuration` مقادیر ناامن شناخته‌شده را در راه‌اندازی رد می‌کند (fail-closed).
- گیت‌های حکمرانی دست‌نخورده‌اند: `AI2_ENABLED=0`، `SCHEDULER_ENABLED=0`، `verified=False ⇒ SYNTHETIC_OR_PAPER`.

## ۴. سطوح داده و برچسب اعتماد

- با `DATA_SOURCE=mock` کل سامانه روی دادهٔ شبیه‌سازی‌شدهٔ قطعی می‌چرخد و هر payload برچسب `data_trust: mock/synthetic/live_verified=false` دارد — UI این افشا را در همهٔ پنل‌ها نشان می‌دهد و هیچ مسیری نمی‌تواند برچسب LIVE را ضرب کند.
- فعال‌سازی منبع زندهٔ واقعی (TSETMC/brsapi) مستلزم مجوز صریح مالک و قاعدهٔ Two-Key برای منابع مهم است؛ بدون آن هر خروجی `SYNTHETIC_OR_PAPER` است.

## ۵. پنل تحلیل چندبعدی (D-O2)

در تب «فیلترنویسی سفارشی» بخش «🧭 تحلیل چندبعدی» — ترکیب ۸ فیلتر مستند + عبارت سفارشی، رتبه‌بندی تعداد تطبیق، حالت رانتی (≥۲ تطبیق). فقط-خواندنی؛ برچسب منشأ هر فیلتر (مستند/RADAR/پیشنهاد) نمایش داده می‌شود؛ خطاها به‌جای حذفِ بی‌صدا صادقانه ثبت می‌شوند.
