## Future implementation gate (not built in P3.84)

To enable a real LLM later, all of the following are required. None are faked here.

1. Provider Adapter — already present (`resolve_ai_provider` / `invoke_ai_provider`)
2. Transport — authenticated HTTPS client, TLS verify on, no client-supplied URL
3. Authentication — server-side key from env only; never logged or returned
4. Timeout — enforce `AI_TIMEOUT_SEC` on the real socket
5. Retry Policy — bounded `AI_RETRY_MAX`; no retry on 4xx
6. Response Schema — validate `{text: str}` (or provider-specific schema) fail-closed
7. Error Mapping — timeout / unavailable / malformed already named
8. Secret Management — env only; redact logs
9. Audit Logging — request id + provider name + status; never prompt/key
10. Data Trust Enforcement — provider must not rewrite `data_trust` or mint LIVE
11. Safety Gate — unverified data cannot be labelled live LLM
12. Provider Health State — `invocation_ready` stays false until transport exists and a credential is present
